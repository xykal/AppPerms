# AppsPerms engineering & security audit — 2026-10-22

Scope: Android application code, Shizuku shell bridge, AppOps flows, manifest, local persistence, Gradle build, and GitHub Actions. This is a source review plus JVM/debug-build verification; it is **not** a substitute for testing on real OEM ROMs.

## Executive summary

The app keeps its strongest privacy property: there is no Internet permission and all Device Care state stays on the device. The new privileged features are bounded and reversible by default. No feature bypasses a third-party license, subscription, premium entitlement, signature check, or DRM.

The most important changes from this audit are:

1. structured privileged commands now validate package names, AppOps and user IDs;
2. Shizuku commands have a 60-second default timeout and a 2 MiB output cap;
3. shell command contents are no longer copied into logcat on failure;
4. obsolete `SYSTEM_ALERT_WINDOW` and `POST_NOTIFICATIONS` permissions were removed;
5. CI unit tests and debug builds now fail the job instead of silently continuing;
6. Debloat has static and dynamic protection for critical packages and current device roles;
7. Debloat snapshots and Feature Lab original values are stored per Android user.

## Findings

| Severity | Finding | Status |
|---|---|---|
| High | CI used `continue-on-error` and `|| echo`, allowing failed unit tests/debug builds to look green. | Fixed in `.github/workflows/build.yml`. |
| Medium | Structured shell methods interpolated package/op values without a central validation boundary. | Fixed with `ShellSafety` and validation in Device Care/AppOps paths. |
| Medium | Shell execution could wait forever and read unbounded output into memory. | Fixed with timeout, concurrent draining, and a 2 MiB retained-output limit. |
| Medium | Failed terminal commands were logged with their full content, which could leak user-entered secrets to logcat. | Fixed; only command length is logged. |
| Medium | The manifest requested overlay and notification permissions even though the related service was disabled. Overlay permission is not required to manage another package’s AppOp through Shizuku. | Fixed; permissions removed. |
| Medium | A naïve debloater can disable the launcher, IME, dialer, SMS app, WebView, device admin, accessibility service, or core framework packages. | Mitigated with an immutable core denylist plus dynamic role protection. |
| Medium | Debloat restore points and feature originals can collide across Android users/profiles. | Fixed with per-user snapshot files and per-user setting keys; global flags use one global owner key. |
| Low | Root cache deletion can race a running app. | Mitigated by explicit confirmation and force-stop before deleting only `cache`/`code_cache`. |
| Low | Cache cleaners are often marketed with inaccurate reclaimed-space claims. | Mitigated by before/after `/data` measurement and honest “attempt” wording. |

## Open risks and follow-up work

### 1. Interactive terminal is intentionally unrestricted

`TerminalActivity` is an explicit shell console and therefore can run any command available to Shizuku/root. This is expected functionality, but it remains the largest capability surface. Recommended follow-up:

- show a persistent root-mode danger banner;
- require an extra confirmation for destructive command patterns (`rm`, `dd`, `mkfs`, `reboot`, package uninstall);
- never add background execution, remote command input, or telemetry;
- consider an optional “safe terminal” mode with an allowlist.

### 2. OEM command compatibility needs a real-device matrix

`pm disable-user`, `pm uninstall --user`, `install-existing`, `pm trim-caches`, and some `settings` flags vary by Android/OEM build. Test at minimum:

- AOSP/Pixel Android 11–16;
- Samsung One UI;
- Xiaomi MIUI/HyperOS;
- OPPO/realme ColorOS;
- Vivo/Funtouch/OriginOS;
- owner, work profile, Secure Folder/clone, and root/non-root Shizuku.

A failed verification is reported as a failure; the app does not claim success only from exit code.

### 3. Hidden API/AppOps bridge remains fragile

The binder path uses hidden interfaces and `HiddenApiBypass`. Shell fallback is a useful resilience layer, but API/OEM changes can still break parsing. Keep parser fixtures from real devices and add instrumentation tests.

### 4. `QUERY_ALL_PACKAGES` distribution policy

The permission is functionally justified for an AppOps/package manager, but app-store review policies may require a declaration or restrict distribution. This is a policy risk rather than a local privacy leak.

### 5. Local backup policy

`android:allowBackup="true"` can include package history and restore metadata in Android backup. No API secrets are stored, but privacy-focused releases should add explicit data-extraction/backup rules or disable backup.

### 6. SDK/dependency modernization

The project compiles/targets API 34. Update compile/target SDK and dependencies in a separate compatibility branch, not together with privileged behavior changes. New target-SDK behavior should be tested before release.

## Device Care safety invariants

- no hard-delete of APKs from `/system`, `/product`, `/vendor`, or APEX;
- no automatic/background cleaner;
- no “drop_caches” RAM placebo;
- no clear-data disguised as cache cleaning;
- no package operation without validated package/user input;
- no mutation of protected packages/current device roles;
- snapshot before the first debloat mutation;
- Feature Lab writes only a fixed allowlist of Android settings and records original values;
- no third-party premium/license/DRM bypass.
